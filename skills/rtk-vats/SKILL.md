# Навык: Виртуальная АТС Ростелеком

Работа с телефонией идёт через сервис **rtk-vats-api** — обёртку над внутренним API
личного кабинета ВАТС (`/webapi`, ~240 эндпоинтов). Доступ: MCP-инструменты `vats_*`
(предпочтительно) или REST с заголовком `X-API-Key`.

Адрес сервиса: `http://127.0.0.1:8010` по умолчанию (в развёрнутом виде — адрес,
который назовёт пользователь). OpenAPI: `/docs`.

## Авторизация: логин + пароль + код из SMS

Один раз на сессию. Дальше сервис держит её сам — токен обновляется в фоне,
пока сервис запущен.

```bash
KEY="X-API-Key: $API_KEY"; H="http://127.0.0.1:8010"

# 0. Проверить — возможно, вход уже есть
curl -s $H/auth/status -H "$KEY"          # authenticated: true/false

# 1. Логин и пароль «Ростелеком Паспорта» -> на телефон владельца уходит SMS
curl -s -X POST $H/auth/login -H "$KEY" -H 'Content-Type: application/json' \
     -d '{"username":"lk_1234567890","password":"..."}'
# -> {"status":"code_required","hint":"Мы отправили код на номер +7 914 …","seconds_to_enter_code":300}

# 2. СПРОСИТЬ КОД У ПОЛЬЗОВАТЕЛЯ и отправить
curl -s -X POST $H/auth/code -H "$KEY" -H 'Content-Type: application/json' -d '{"code":"123456"}'
# -> {"status":"ok","seconds_left":1435,"has_refresh_token":true,"has_fingerprint":true}
```

MCP: `vats_auth_status` → `vats_auth_login` → `vats_auth_code`.

Правила этого шага:

- **Учётные данные спрашивать у пользователя**, если он их не дал. Пустые `username`/`password`
  означают «взять из конфигурации сервиса» — это нормальный вариант, сначала попробовать его.
- **Код из SMS никогда не выдумывать и не подбирать.** Спросить и дождаться. Неверный код тратит
  попытку, а повторную SMS Паспорт присылает с задержкой.
- На ввод кода есть ~5 минут (`seconds_to_enter_code`). Не успели — начать с `/auth/login` заново.
- SMS не пришла или передумали — `POST /auth/cancel` (`vats_auth_cancel`), чтобы не держать попытку.
- Проверить, что сессия живая и продлевается — `POST /auth/refresh` (`vats_auth_refresh`).

Ответ **503 / `auth_required`** от любого другого роута = сессия потеряна, начать вход заново.

### Если вход не проходит

- `501` — на сервере не установлен браузерный движок. Варианты: поставить
  (`pip install playwright && playwright install chromium`), либо войти с машины пользователя
  через `python scripts/login_helper.py --api-url <адрес сервиса> --api-key <ключ>`,
  либо импортировать токены вручную (`/auth/import`, см. `references/pbx-setup.md`).
- `400` с текстом от Паспорта («неверный логин или пароль») — вернуть текст пользователю как есть.
- Домен без SSO (собственный пароль в самой ВАТС) — там работает классический
  `POST /auth/start` + `/auth/complete`. Для доменов «Ростелеком Паспорта» он отвечает
  «Введенные учетные данные некорректны» — это не ошибка сервиса.

## Основные операции

```bash
KEY="X-API-Key: $API_KEY"; H="http://127.0.0.1:8010"

curl -s $H/balance  -H "$KEY"            # баланс — проверять ПЕРЕД изменениями
curl -s $H/contacts -H "$KEY"            # адресная книга: группы + контакты
curl -s $H/contacts/users -H "$KEY"      # абоненты домена (номера, PIN)
curl -s $H/users    -H "$KEY"            # пользователи домена
curl -s $H/groups   -H "$KEY"            # группы обработки вызовов
curl -s $H/numbers  -H "$KEY"            # номера и правила маршрутизации
curl -s $H/settings -H "$KEY"            # настройки домена
curl -s "$H/calls?date_from=2026-08-01" -H "$KEY"        # история звонков
curl -s "$H/calls/stat?date_from=2026-08-01" -H "$KEY"   # статистика
curl -s $H/calls/<callId>/protocol -H "$KEY"             # протокол звонка
curl -s $H/calls/<callId>/record   -H "$KEY" -o call.wav # запись разговора

# Контакт и группа контактов
curl -s -X POST $H/contacts -H "$KEY" -H 'Content-Type: application/json' \
     -d '{"name":"Иванов И.И.","numbers":[{"number":"89140000000","contactType":"mobile"}]}'
curl -s -X POST $H/contacts/groups -H "$KEY" -H 'Content-Type: application/json' -d '{"name":"Врачи"}'

# Всё остальное — прозрачный прокси (путь после /webapi)
curl -s "$H/proxy/domain/settings/nextpin" -H "$KEY"
curl -s -X POST "$H/proxy/callcenter/reports/by_calls" -H "$KEY" \
     -H 'Content-Type: application/json' -d '{"date_from":"2026-08-01"}'
```

Модели тел запросов «мягкие»: лишние поля уходят в ВАТС как есть, можно передавать
полные структуры ЛК.

## Настройка АТС

Схемы абонента, группы, IVR, правил маршрутизации и расписаний, карта эндпоинтов и
приёмы поиска новых — в **`references/pbx-setup.md`**. Читать перед правкой маршрутизации.

## Правила

- **Сначала `/auth/status` и `/balance`**: большая часть «странных» ошибок — это потерянная
  сессия или отрицательный баланс. При долге домен блокируется: GET-запросы работают,
  а POST/PUT отвечают «Домен заблокирован. Пополните счёт» — это не поломка сервиса.
- **Читать свободно, писать — с подтверждением.** Создание/удаление абонентов, групп,
  правил маршрутизации и IVR меняет боевую телефонию: показать, что будет сделано, и дождаться «да».
- **Обещанный платёж** (`POST /proxy/domain/payments/promised_payment`) — только по явной
  команде пользователя: это финансовое обязательство.
- Не выдумывать пути: нужного метода нет в удобных роутах — искать в `references/pbx-setup.md`
  или в JS-бандле ЛК, затем звать через `/proxy/...`.
- Записи разговоров и персональные данные абонентов наружу не отправлять, хранить локально.
- Пароли, токены и коды из SMS не печатать в ответах и не коммитить.
